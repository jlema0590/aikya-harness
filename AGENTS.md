# Aikya contributor instructions

Use the approved Aikya workflow and preserve explicit user authorization. External
authoring skills may assist the task; adapt their default output locations to this
repository's documentation contract.

- Write all new first-party plans under `aikya/docs/plan/` (singular), bug records
  under `aikya/docs/bugs/`, and feature records under `aikya/docs/features/`.
  Never create root-level plans/, bugs/ or features/ for Aikya records.
- Write research and validation reports under `aikya/docs/research/` and
  `aikya/docs/validation/`; refresh `aikya/docs/indice.md` after approved writes.
- Keep SDD plan.md in its authoritative `aikya/docs/specs/<project_type>/SPEC-NNN/`
  dossier and ODD feature records under `aikya/docs/features/<slug>/`.
- Keep source and engineering instructions English. Project living documents
  follow the configured en/es policy. End authored Markdown once with
  `GENERATED BY AIKYA HARNESS`.
- Preserve root project contracts and functional instruction/template asset paths.
  Existing project-owned documentation is not automatically relocated or deleted.
- Historical guides under docs/ remain until the separately reviewed consolidation
  plan is implemented. Do not add new first-party reports or planning directories
  there or directly at the repository root.
- Run checks appropriate to the change and record only observed results. Source
  quality, methodology approvals and configured security checks remain separate
  controls; a planning document does not approve implementation or deployment.
