# Project-specific Claude instructions

Aikya creates a root CLAUDE.md when it is absent during approved initialization or
existing-repository analysis. The instructions stay English even when living docs
use Spanish. Existing CLAUDE.md files remain byte-for-byte owner-controlled,
including previous generated contracts. Review the profile rule alongside them.

## Composition

| Recorded input | Selected instructions |
|---|---|
| project_type=development | Application behavior, interface compatibility and configured tests |
| project_type=infrastructure | Resource ownership, state, scoped change planning and cost impact |
| project_type=devops | Pipeline permissions, artifacts, environment promotion and rollback |
| repository_layout | Existing/approved root or explicit workspace boundaries |
| Selected stack and infrastructure | Only the language, platform and tools present in the profile |
| methodology=sdd | Separate specification, plan and task approvals with real execution evidence |
| Detected modules | Observed path indicators, without claiming audited source or successful checks |

The base lives in template/CLAUDE.md; the three type fragments live in
claude-templates/. claude_templates.py renders them offline during installer
preflight, before project mutations. Both global and project bootstrap runtimes
include the renderer and assets. No template command runs automatically.

There are no assumed package scripts, coverage thresholds, SDK versions, cloud
services or orchestration integrations. Confirm concrete commands through actual
manifests and harness.json. A recorded choice is not proof of an installed stack.
Missing checks remain NOT VERIFIED. Every generated contract has one terminal
GENERATED BY AIKYA HARNESS footer and stays below 200 lines for bundled examples.

## Sole external template reference

The standing-instructions structure uses the pinned Aikya reference collection
`aikya-template/docs/ai-assisted-development/foundations/agent-instructions-file.md`:
project context, real commands, conventions and boundaries. Aikya supplies its
existing project-type adapters, scope rules and methodology gates. Commands are
selected from actual configuration rather than copied from upstream examples.
Missing project facts do not create extra empty sections. The generated contract
records this source; existing CLAUDE.md remains protected.
