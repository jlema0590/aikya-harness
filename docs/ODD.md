# Organic Driven Development (ODD)

Aikya offers **ODD** and **SDD** during `/aikya-init` and `/aikya-analyze` for
new/existing development, infrastructure and DevOps projects. ODD is recommended;
the initial choice must be explicit. Without it, the CLI returns
`NEEDS_METHODOLOGY`, both options and `writes=false`. A confirmed profile retains
its choice on refresh. The legacy input `standard` normalizes to `odd`.

ODD scales the record to the work. If the change is understood, its risk is
contained and the request plus diff provide enough continuity, use the existing
REQ audit with acceptance and actual verification. Investigation creates no
implementation dossier. Otherwise, review an objective, acceptance criteria and
bounded tasks before changing code. Classification uses explicit boolean facts;
router suggestions do not authorize work.

## Substantial work

The recorder uses the pinned Aikya reference collection agent-task specification and task plan,
composed with Aikya acceptance criteria. It creates:

```text
aikya/docs/features/<lowercase-slug>/
  spec.md       # Reviewed objective, acceptance, task projection and next step
  state.json    # Versioned worklist, dependencies, revisions and evidence hashes
```

Only Markdown receives the exact final line `GENERATED BY AIKYA HARNESS`.
`aikya/docs/indice.md` lists generated Markdown. Tasks reference `AC-NN` acceptance
criteria, scoped project files and planned checks. Checks are data; the recorder
never executes them, deploys, installs dependencies or certifies their outcome.

```sh
python3 aikya/scripts/harness/odd_engine.py classify --input facts.json
python3 aikya/scripts/harness/odd_engine.py new --root . --id lookup --input reviewed.json --approved
python3 aikya/scripts/harness/odd_engine.py resume --root . --id lookup
python3 aikya/scripts/harness/odd_engine.py progress --root . --id lookup --task TASK-001 --result done --revision 1 --evidence checks/lookup.log --approved
```

Use `in_progress` or `blocked` while work or checks remain. `done` requires actual,
nonempty evidence files and completed dependencies. A result is recorded evidence,
not independently executed verification. The caller must first perform and review
the relevant checks and record its own Validate/Security outcome.

The recorder rejects stale revisions, cycles, unsafe paths, secret `.env` paths,
missing evidence, custom documents and evidence made only from its own dossier.
It detects changes to completed task files or evidence on resume. Review the
current diff, then invalidate stale tasks and dependents explicitly:

```sh
python3 aikya/scripts/harness/odd_engine.py reconcile --root . --id lookup --revision 3 --approved
```

External edits to `spec.md` remain protected. Reconcile the reviewed state and
document manually before continuing; the command does not overwrite those edits.
Reopening a completed task also invalidates dependent completions and retains
history. Small changes still follow the existing REQ documentation gate.

## SDD remains separate

SDD keeps specification, plan and task approvals plus its evidence and traceability
gates. ODD cannot authorize an SDD task. Switching an existing SDD profile to ODD
requires a separately reviewed migration. Selecting SDD for an owned ODD project
is explicit, preserves technical decisions and previews generator/gate changes.
Known legacy profile/answers migrations retain backups under `.harness/backup-odd/`;
unknown coupled runtime edits require review before installation changes anything.
