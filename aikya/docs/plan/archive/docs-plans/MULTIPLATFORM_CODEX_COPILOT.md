# Future assistant interoperability — design proposal only

> Archive status: Archived unimplemented proposal. These requirements do not describe delivered assistant adapters.

Claude Code remains the supported command adapter in this delivery. This document
does not implement or verify integrations with Codex, GitHub Copilot, Gemini CLI,
Cursor, Windsurf or another host.

## Proposed architecture

Keep profiles, specifications, approvals, tasks and evidence in a Python core with
versioned schemas. Host adapters should map available reading/writing, execution,
approval and agent capabilities to that contract. A missing host capability must
produce an explicit limitation or stop, never simulated execution.

The portable CLI alone does not establish multi-host compatibility. Review each
host's current instructions, skill formats, sandbox and permission model before
implementation; do not copy Claude hooks or assume identical behavior.

## Possible roadmap

1. Stabilize shared schemas, migrations, structured results and portability tests.
2. Prototype a Codex adapter with repository instructions and supported skill discovery.
3. Prototype GitHub Copilot instructions, agents and prompts for each intended client.
4. Evaluate Gemini CLI, then bounded Cursor/Windsurf adapters against actual capabilities.
5. Publish a compatibility matrix only after reproducible host-specific acceptance.

## Acceptance per future adapter

- Non-destructive installation, project/user scopes and reviewed reversal.
- At least six equivalent SDD operations with shared IDs and state.
- No mutation in read-only mode and independent remote-operation approval.
- Development, infrastructure and DevOps acceptance in a credential-free sandbox.
- Custom-file, approval, path and secret-protection checks.
- Versioned adapter contract and reproducible evidence with documented limits.
- Review redistribution rights before bundling external skills.

These are future requirements, not implemented features of 6.1.1.
