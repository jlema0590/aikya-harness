# Latest Release Installation Implementation Plan

**Goal:** Install the latest published stable Aikya release by default on Linux, macOS and Windows; prepare version 7.0.1 without publishing a release.

**Architecture:** Share release selection in the standard-library bootstrap. Resolve GitHub's latest stable release once, validate its numeric tag, then use immutable version URLs and existing checksum/wheel validation. Platform scripts retain their embedded bootstrap checksum; online calls select the latest wheel, while offline calls use their own release version unless explicitly overridden.

**Tech Stack:** Python 3.10–3.13 standard library, POSIX shell, PowerShell 5.1+, unittest.

## Constraints and review focus

- Preserve explicit global/project scope, existing ownership safeguards, generated runtime assets and ODD/SDD behavior.
- Retain `--version X.Y.Z` / `-Version X.Y.Z`; default and `latest` mean GitHub's published stable release, never a branch, draft or prerelease.
- Reject malformed metadata, invalid tags and failed network requests before provisioning; do not silently install an older version.
- Offline bootstrap usage requires an explicit numeric version; release entry scripts supply their embedded version offline.
- Keep HTTPS allowlisting, bounded metadata reads and SHA-256 verification. Resolve once so a newly published release cannot mix assets during installation.
- Keep documentation under `aikya/docs/`, refresh the index and retain the required Markdown footer.
