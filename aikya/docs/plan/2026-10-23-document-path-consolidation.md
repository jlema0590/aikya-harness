# Canonical Documentation Paths Implementation Plan

> **For Aikya contributors:** Implement this plan task by task using the approved Aikya workflow. Verify each change and preserve explicit user approvals. Use the checkboxes to record observed completion.

**Goal:** Keep first-party generated plans/reports under aikya/docs/, detect misplaced future reports and migrate known historical documentation without deleting project-owned docs.

**Architecture:** Repository instructions override external authoring-skill defaults. Canonical writers remain shared; docs_guard validates document locations before its no-source-change early return. A source/destination migration map handles historical first-party files and link rewrites, while an explicit runtime asset mapping preserves bundled guide locations independently from their source locations.

**Tech Stack:** Python 3.10–3.13 standard library, existing docs_layout/docs_guard, Git path inventories and unittest.

**Spec:** [Installer and documentation path audit](../research/2026-10-23-installer-doc-path-audit.md), actual locations, clean-target reproduction and reproduced enforcement gap. Baseline: 40bce20.

## Global Constraints

- New first-party plans use aikya/docs/plan/ (singular); no new root docs/, plans/ or plan/ for generated Aikya reports.
- Retain authoritative SDD dossiers at aikya/docs/specs/<project_type>/SPEC-NNN/plan.md and ODD feature dossiers at aikya/docs/features/<slug>/spec.md.
- Preserve root project contracts, executable instruction assets, pinned third-party catalogs and the explicitly external private-memory store.
- Do not edit the user's globally installed writing-plans skill. Local repository/project instructions take precedence over its default path.
- Do not delete or move an existing project's docs directory simply because it is named docs. Legacy import continues preserving originals.
- Every authored Markdown ends once with GENERATED BY AIKYA HARNESS; project documents follow the configured en/es policy.
- Migration preview is read-only; apply verifies content hashes, symlink safety, destination conflicts and backups before changes.
- This plan does not authorize live model calls, dependency installation, pushes or publication.

## Review Focus

- A generated report outside aikya/docs must not pass CI merely because the diff contains no code.
- A project-owned docs/ tree or third-party instruction template must remain byte-for-byte untouched.
- Re-running or resuming a migration must not overwrite a destination edited after the preview.
- Moving a source guide must not break global/project runtime packaging or create a second nested documentation tree.
- Markdown/image links, anchors, historical references and the index must still resolve after files move.
