# Plan de implementación: eficiencia de tokens y memoria de código

**Estado:** implementación local autorizada el 29 de octubre de 2026. Sin cambios
en `jourpass_app`, modelos globales ni publicación remota.
**Rama:** `feat/token-efficiency`, develop `177f032` más dependencia Memory `512dea2`.
**Fecha:** 29 de octubre de 2026.
**Ejecución propuesta:** secuencial, con pruebas por tarea y revisión de cada entrega.
**Objetivo:** aprovechar la memoria local para consultar código relevante y reducir
contexto y pasos repetidos, manteniendo aceptación, seguridad y auditoría.
La validación es transversal a todos los lenguajes, extensiones y stacks actuales
de Aikya; Dart es la ampliación prioritaria, no el único lenguaje bajo prueba.
**Arquitectura:** ampliar el índice y los motores locales existentes; añadir una
entrada compartida de contexto para comandos y loop, sin otro almacén de memoria.
Separar medición de tokens, decisiones del workflow y cuotas del proveedor.
**Tecnologías:** Python 3.10–3.13, SQLite, adaptadores Tree-sitter opcionales,
JavaScript del visor, unittest y CI existente de Linux/macOS/Windows.
**Especificación y evidencias:**
[informe de investigación](../research/2026-10-29-token-efficiency-jourpass.md) y
[recibo saneado](../research/2026-10-29-token-efficiency-jourpass.json).
Ampliación: [auditoría de los 28 comandos](../research/2026-10-29-all-command-token-audit.md)
y [mediciones de instrucciones/backends](../research/2026-10-29-all-command-token-audit.json).

## Resultado esperado y límites

Después de la primera entrega, una petición como «modifica el método de inicio de
sesión» podrá consultar clases/métodos Dart indexados, recibir fragmentos actuales
y localizar archivos relevantes antes de explorar más código. Si no hay coincidencia,
el índice está desactivado o falta el parser, se indicará la limitación y se hará
una lectura acotada de fuente; no se inventará memoria ni se bloqueará un cambio
legítimo sólo por ausencia de caché.

La memoria, el índice y la generación del HTML continuarán siendo locales y sin
llamadas a modelos. La IA consume tokens al interpretar la petición y el contexto
recuperado. Un comando slash también pasa por el asistente: no se promete consumo
cero por invocarlo. La cuota de 5 horas/semanal no se calcula a partir de una suma
de tokens ni puede limitarse globalmente desde Aikya.

La sesión observada contiene 244 mensajes con uso registrado y un 97,36% de lecturas
de caché. Es una referencia diagnóstica, no un benchmark comparable ni una factura
por comando. La comparación de ahorro utilizará tareas y condiciones controladas.

## Restricciones globales

- Todo plan, bug, feature e informe nuevo permanece dentro de `aikya/docs/`.
  Código e instrucciones de ingeniería en inglés; README en inglés y español.
  Los Markdown generados terminan una sola vez con `GENERATED BY AIKYA HARNESS`.
- Reutilizar SQLite, `ParsedFile`, consultas, observador, guard documental y
  políticas actuales; no añadir base vectorial, servicio externo ni extracción LLM.
- Mantener comprobación de hashes, identidad por proyecto/worktree, exclusiones,
  límites de archivos, protección frente a symlinks y notas revisadas/no caducadas.
- No confundir relaciones estáticas con ejecución ni `complete` con cobertura
  semántica de todos los lenguajes. No usar regex como prueba de clases Dart.
- No instalar parsers, cambiar modelo o activar agentes silenciosamente.
  Una política de eficiencia nunca aprueba una fase SDD ni sustituye security/review.
- Preservar HTML/reporte firmado, documentos personalizados, caché y notas del usuario.
  Cambios de esquema necesitan lectura compatible o migración explícita recuperable.
- Mantener la API actual de `query()` y los comandos existentes durante la transición.
  Las interfaces adicionales descritas aquí son propuestas, no comandos ya disponibles.
- Aplicar la calidad de fuente existente: reutilización de helpers y modularización
  por responsabilidad, sin introducir archivos de fuente por encima de 1000 líneas.
- La versión de trabajo es 7.1.1. Proponer 7.2.0 para estas capacidades aditivas,
  verificando la siguiente versión disponible antes de preparar la publicación.

presupuesto, exclusiones y estado de cobertura. Unicode/CRLF, errores de sintaxis

React, Vue, Angular, Flutter, React Native/Expo, Android nativo Java/Kotlin e iOS
SwiftUI/UIKit. Astro/Tailwind tiene agente y skill de ingeniería y se prueba por

Para infraestructura/DevOps, incluir Terraform/OpenTofu, Docker/Compose,
Kubernetes, Helm/Kustomize, Ansible y las opciones actuales de CI. YAML/JSON,
HTML/CSS/SCSS, `.astro`, manifiestos y plantillas se prueban como entradas del
workflow correspondiente. Si no entran en el índice de código actual, comprobar
esa limitación expresamente; no ampliar silenciosamente la lista de formatos ni
presentarlos como archivos indexados. Excluir valores secretos de `.tfvars`.

Usar fixtures pequeñas y una de monorepo políglota. Cubrir las rutas compatibles
de los comandos, ODD/SDD y proyecto nuevo/existente mediante casos representativos
y combinaciones por pares; no generar el producto cartesiano de opciones inválidas.
Una prueba de parser no acredita compilación/build de la aplicación: registrar
aparte las comprobaciones que necesitan SDK/toolchain y sus omisiones justificadas.

Esta ampliación exige validar todas las capacidades actuales; no promete añadir
parsers nuevos para todos los lenguajes `file_only` en esta versión. Kotlin/Swift
y las demás brechas quedan visibles en el informe de cobertura para priorizarlas.

no cero. Nunca asignar un cambio porcentual de cuota a un comando sólo por su horario.

**Tres rankings separados:**

1. Instrucciones estáticas: Implement (~2362 unidades proxy), Feature (~2171),
   Bugfix (~2124). Un bloque idéntico de observación de 1658 caracteres aparece

2. Salida local medida: Analyze 48.637 bytes e Init hasta 48.477 por proceso de

3. Ventanas reales de la sesión seleccionada: Memory 19,57 M, Analyze 13,39 M,

Estas evidencias priorizan respuestas compactas y consultas simples, además de
la recuperación Dart. La tarea 1 convierte la medición en un contrato reproducible;
las tareas 5/6/8 corrigen los factores y la tarea 9 compara todos los comandos.
Los comandos de Mods tienen otro catálogo; no se mezclarán silenciosamente con
los 28 nombres canónicos de Harness.

## Focos de revisión

1. Archivos Dart con Unicode, CRLF, constructores, mixins y sintaxis no soportada:
   rangos correctos; un error no publica símbolos obsoletos como actuales. Tarea 2.
2. Código modificado, renombrado o borrado tras indexar y consultas desde otro worktree:
   verificar identidad/hash antes de recuperar; nunca reutilizar una prueba ajena. Tarea 4.
3. Instalación limpia sin extras, plataforma sin binario o bundle offline incompleto:
   conservar runtime activo y mostrar cobertura limitada, sin compilación oculta. Tarea 3.
4. Reanudación del loop, streaming duplicado, cancelación y uso incompleto:
   conservar límites consumidos y no inventar contabilidad. Tareas 1 y 7.
5. Cambios pequeños de ODD y comandos informativos: evitar expedientes/reintentos
   innecesarios sin omitir una obligación real de documentación o seguridad. Tareas 5 y 6.
