# Installer Modularization Implementation Plan

> **For Aikya contributors:** Implement this plan task by task using the approved Aikya workflow. Verify each change and preserve explicit user approvals. Use the checkboxes to record observed completion.

**Goal:** Reduce install.py to a compatible entry point and facade, eliminating its 1,309-line concentration of unrelated responsibilities without changing installed-project behavior.

**Architecture:** Extract an aikya_installer package with one-way dependencies. install.py retains the existing 28 callable names and public constants, including HERE and TEMPLATE, because CLI, analysis, profile construction and tests consume them. Package asset roots are passed through an explicit context so repository, global, project and initialized runtimes resolve the same resources.

**Tech Stack:** Python 3.10–3.13, standard library, unittest, existing installation and asset validation.

**Spec:** [Installer and documentation path audit](../research/2026-10-23-installer-doc-path-audit.md), requirements, verified size and acceptance targets. Baseline: 40bce20.

## Global Constraints

- Version remains 6.1.1 unless the user separately requests a release change.
- No file above 1,000 physical source lines; aim for coordinator helpers below the existing 100-line warning threshold.
- Preserve install.py signatures, public constants, return values, action semantics and caller-visible errors.
- Preserve init/analyze, ODD/SDD, development/infrastructure/DevOps, global/project, en/es and existing bootstrap-only protection.
- dry_run must not write or launch external tools; no generators, SDK installation, deployments or live model calls.
- Preserve custom files, CLAUDE.md, settings, approved methodology and migration backups.
- Keep first-party authored planning documents under aikya/docs/plan/; each authored Markdown ends once with GENERATED BY AIKYA HARNESS.
- Keep path-policy behavior changes in the separate document-consolidation plan. This refactor must not silently migrate root documentation.

## Review Focus

- Installed CLI executed from an unrelated working directory must find the package and catalogs.
- An upgrade with a customized runtime dependency must stop before replacing the facade with incompatible imports.
- Source-root resolution and HERE/TEMPLATE compatibility must not accidentally refer to the package directory instead of the runtime root.
- Mid-copy failure and existing backup collisions must preserve the original custom content and allow an inspectable retry.
- Moving defaults or imports must not change new/existing, method, locale or project-type choices.

| aikya_installer/io.py | Existing safe_write and merge_settings behavior; settings functions receive context. |
| aikya_installer/migrations.py | Existing verified upgrades, legacy import, path checks and backup behavior; receives context and uses io. |
| aikya_installer/assets.py | Runtime/template/catalog copying with focused helpers and a shared runtime_assets(context) -> list[tuple[Path, Path]] inventory. Destination paths are relative to a runtime root. |

| install.py | Compatible wrappers/re-exports and CLI; no package module imports this facade. |

Dependency direction: context/discovery/profile → interview/checks/documents/io →
migrations/assets → pipeline → facade. Reuse existing documentation, SDD, catalog
and execution modules. Do not copy their implementations into the new package.
