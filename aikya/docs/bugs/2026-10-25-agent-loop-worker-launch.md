# Agent Loop Worker Resolves a Retired Root Adapter

Status: **Fixed and verified locally; 538 regression tests passed.** Original priority: **P1** for direct package SDK execution.

Audited commit: `de512aa6066d7e75232c62c485f267681b2c48a1` (repository VERSION 7.0.1).

## Trigger and actual result

At the audited revision, `ProcessRuntime()` builds its default subprocess command in `src/aikya/core/runtime.py:20` as `sys.executable -B <source_root>/agent_runtime.py worker`. The root adapter was removed during package migration, and the wheel's `resources/distribution/` does not contain it either.

Running the selected worker with `check` exits 2 with `can't open file` / `No such file or directory` in both environments:

- Source checkout: `<checkout>/agent_runtime.py` does not exist.
- Independently installed local 7.0.1 wheel: `<package>/aikya/resources/distribution/agent_runtime.py` does not exist.

This reproduction only starts Python against the selected path. It does not need the SDK, authentication or a model request. Source inspection confirms the same nonexistent path is selected for `worker` execution when the SDK preflight succeeds.

## Impact and why existing tests passed

The optional task loop and model-assisted memory extraction both use the default `ProcessRuntime`, so direct source/wheel SDK execution cannot start through the broken command. Registered and initialized copies still contain an adapter and passed their startup checks even before the correction; the failure does not apply to every copied runtime. This is separate from the intentional explicit opt-in requirement. Local memory add/propose/review/recall does not use the SDK worker and remains functional.

`available()` checks whether `claude_agent_sdk` is importable; at the audited revision it does not detect the selected missing worker entry point. Without the SDK, the loop returns `optional_sdk_missing` before reaching the missing-file failure.

Existing loop/extraction success tests inject `tests/fixtures/agent-loop/worker.py`. Installation tests cover the SDK-missing path. The SDK contract check exercises options and hooks rather than starting the default worker. These checks do not prove that the default SDK worker launches.

## Correction and acceptance

- Launch the canonical package module with the selected interpreter, preserving runtime isolation and custom fixture command support, instead of reconstructing a retired root filename.
- Add behavioral startup coverage in a source environment, an isolated installed wheel, and registered/initialized runtimes. Exercise the default command with an available controlled SDK stand-in and no provider/model request; keep authenticated execution as a separate acceptance gate.
- Update optional-runtime setup examples that still assume root source adapters and document how the chosen interpreter obtains both Aikya and its optional SDK.
- Retain explicit task approval, file/check scope, cost/time/turn budgets and independent review. Fixing the entry point must not silently enable the loop.

The local correction uses the current interpreter with `-I -B`, pins the currently loaded package's parent directory, and executes `aikya.core.runtime` through `runpy.run_module`. Custom worker commands remain supported. Red tests reproduced missing-file failures in the source and independently built/installed wheel; the same tests pass with the correction. The default worker's `check` also succeeds with the real installed pinned SDK without making a provider request.
