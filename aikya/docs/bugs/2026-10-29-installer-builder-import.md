# Clean installer builder could not import the parser manifest

## Trigger and root cause

PR #25, installer workflow run `40875522151`, failed in the build job with
`ModuleNotFoundError: No module named 'aikya'` at the parser bundle script import.
The clean runner built the distributions but had not installed the package before
executing `scripts/ci/parser_wheels.py`. The repository uses a src layout, so the
built wheel is not automatically importable from the checkout. Contributor/local
editable installation had hidden this missing workflow step. The release packaging
job already installs the contributor package before this command.

## Correction

After building, the clean installer job installs `aikya-harness` from its local
`dist` wheel with `--no-deps --no-index --find-links dist`, before preparing parser
bundles. No import-path override or dependency resolution from an index is added.
The workflow's Python 3.11 interpreter imports the same package it just built.

## Observed verification

- A fresh temporary virtual environment without Aikya reproduced the import failure
  even with `parser_wheels.py --help`.
- Built v7.2.0 source/wheel successfully and installed only that wheel into the
  clean environment; parser bundle CLI then loaded successfully.
- The actual bundle command downloaded all seven pinned binary requirements for
  Linux x86_64/CPython 3.11; it did not load or execute those foreign binaries.
- Built the bootstrap and both installer scripts. After including the source ZIP
  required by the release contract, asset validation and SHA-256 checks passed.
  An initial release-contract invocation correctly rejected the fixture without
  that ZIP; it was a validation-fixture omission rather than another product defect.
