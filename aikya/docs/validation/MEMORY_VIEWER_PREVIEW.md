# Memory viewer design preview validation

**Date:** 2026-10-25. **Scope:** the standalone [HTML design example](../examples/aikya-memory-preview.html), not a registered `/aikya-memory` command or a production memory export.

The example embeds 19 nodes and 19 edges from selected repository files. Python declarations and locations were read with `ast`; document links were checked against the actual plan files. It contains three source files, ten declarations, two documents, three folders and the project node. No reference memories were fabricated. The page explicitly identifies this selected sample.

## Observed browser checks

An installed Chromium headless browser opened the HTML through `file://` in an offline context. All **15 checks passed**:

1. Offline loading and repository node counts.
2. Reveal animation starts, finishes and leaves no continuous animation.
3. Pointer selection displays the function and its source lines.
4. Keyboard selection changes the detail immediately, without animations.
5. Search filtering and the no-results state agree with the node count.
6. Type filters update the graph and totals.
7. Inventory and graph share the selected node.
8. Focus and rapid zoom settle without queued animations.
9. Light and dark themes switch correctly.
10. Motion off stops animations and transitions and disables replay.
11. An HTML-shaped label is displayed as text in the inspector.
12. The desktop layout has no overlapping footer or horizontal overflow.
13. The 390 px mobile layout keeps a visible graph and has no horizontal overflow.
14. System reduced motion prevents animated movement.
15. No HTTP requests, page errors or console CSP violations were observed.

The check script and diagnostic logs were temporary validation tools outside the repository. Desktop and mobile screenshots were visually inspected; the retained [desktop capture](../examples/aikya-memory-preview.png) shows the example's overview. The screenshot is static; open the HTML to inspect its animation.

## Changes informed by verification

- Cancel active transitions before keyboard handling and when motion is disabled; changing CSS duration alone did not stop transitions already in progress.
- Remove a graph-height dependency that overlapped the desktop footer, and place the base height rule before responsive overrides so the mobile graph remains visible.
- Keep animated focus interruptible using its currently rendered transform.

## Limits and planned follow-up

It does not collect the project's memory, create a code index, install software, publish artifacts or implement the planned slash command.
